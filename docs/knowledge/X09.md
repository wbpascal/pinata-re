## 4. Which broadcasts stop at sight (Z01 §3.2 against `s45`'s shout; code read in part 4)

§3's open point is settled by the code (zone export with the 2016 PDB, `re-data/exports/zone-pdb`): Z01 §3.2 is
too general; Z02 §3.2 and `s45` (capture-validation §27.4) are right.

- `ShineObject::so_AllInMap` FUN_0054b8c0 (profiler `so_AllInMap0`) and its iterator overload FUN_0054b9e0
  (`so_AllInMap1`) only call the field's pointers `FieldMap.fm_BroadFunc.fm_fp_AllInMap1` / `fm_fp_AllInMap2`.
  `FieldMap::fm_Init` FUN_00464bc0 sets them to `so_AllInMapMiniHouse` FUN_00553c60 / FUN_00553dd0 on a
  mini-house field, otherwise (and in the constructors FUN_00466170, FUN_004662e0) to `so_AllInMapNomal`
  FUN_0054be00 / FUN_0054c370.
- `so_AllInMapNomal` (both overloads; the iterator one FUN_0054c370 is the one `AxialListPacketBroadcast` goes
  through) walks the object's whole Y-sorted list (`so_slantedlist.Ylist`) in both directions, up to 10 000 objects
  each way (then it logs to `BroadCastLog` and stops), and calls the visitor's `ali_Work(sender, object,
  so_DistanceSquar(sender, object))` for every object on the same layer (`LayerRegistInfo.nLayerNumber` and the
  next 4 bytes equal) or when either object's `LayerRegistInfo.nViewType` ≠ 0: it computes the distance but **does
  not limit it**. With its flag argument set it ends with `ali_Work(sender, sender, 0)`.
- `AxialListPacketBroadcast::ali_Work` FUN_00428b20 ignores that distance argument. Its checks: packet length ≠ 0,
  receiver type 2 (player, vt 0x4d0) and vt 0x484 true, `layer->l_Main` equal or either −1,
  `so_SubLayer_CanSee` FUN_0049ac70 (= `sublayerview.sli_Interactive[sender l_Sub][receiver l_Sub]`, a
  sub-layer matrix, **not** a sight test: Z01 §3.2 reads it as "in sight"), receiver not closing (vt 0x300), the
  "hide except me" rule (vt 0x79c), then the send.
- The sight radius comes only from `so_AllOfRange`: FUN_0054baf0 (`so_AllOfRange_Class0`) and its iterator overload
  FUN_0054bc80 (`so_AllOfRange_Class1`, the one the emote relays and Z02 §1's "broadcast to sight" use) turn a
  radius argument of 0 into `MapInfo.Sight` of the field, or 99 999 999 when the object's `so_eSightState` is
  `OSS_WIDE` or the field's `fm_CameraState` is `CS_MOVING`, and call `fm_fp_AllOfRange1` / `fm_fp_AllOfRange2`.
  `so_AllOfRangeNomal` FUN_0054d360 (read in part 5) bounds its walk of the X and Y lists by x / y ± radius and
  compares with radius²; its other overload FUN_0054c900 was not read, and that `fm_Init` sets the two pointers to
  these two is *(inferred)* from the names. Which senders use `so_AllOfRange` and which
  `so_AllInMap` is per sender (Z02 §3.2: the shout uses `so_AllInMap1`, so the whole map, as captured).
- Effect on the ratings: the hand row Z01 §3.2 stays medium with this reason (`X02-rate-hand.py`, block "X09
  part 3"). Z01 is done and its text is not changed here (plan "Goal": this item edits only X02's two files and this
  one); the README §5 superseded-statement row is follow-up item X10 (§7's first row).
