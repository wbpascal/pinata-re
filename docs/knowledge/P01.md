# P01: Packet capture decoder (`tools/protocol-re/pcap_decode.py`)

Pure-Python (stdlib only) decoder for Wireshark captures of client↔server traffic. It applies the rules in
`docs/protocol/README.md` §1 and checks each packet against the documented layouts.

## Usage

```bash
python3 -I tools/protocol-re/pcap_decode.py re-data/captures/<name>.pcapng          # writes <name>.pcapng.{decoded.txt,report.md,json}
python3 -I tools/protocol-re/pcap_decode.py cap.pcapng --port 19010=login --port 19110=wm --port 19210=zone
python3 -I tools/protocol-re/pcap_decode.py cap.pcapng --out /some/dir --show-secrets
python3 -I tools/protocol-re/pcap_decode.py --transcript server/test/replay/transcripts cap.pcapng   # ADR 0008 transcript only
python3 -I tools/protocol-re/pcap_decode.py --selftest
```

- Default port map: every `SERVER_INFO` row with type 20 in `Files/Server/2016/9Data/ServerInfo/ServerInfo.txt`
  (Login 9010, WM 9110, zones 9210/9212/9214/9216), plus the server-link listeners (types 0–3, 5, 6: AccDB 9000,
  Login←WM 9011, WM←zone 9111, zone links 9218–9221, ALDB 9311, W00_CDB 9411, W00_GLDB 9511) as kind `link`.
  `--port PORT=login|wm|zone|link` adds or overrides one port.
- Server links (added by P02): plaintext (no seed, no cipher); stream id = listener name from ServerInfo.txt
  (`W00_CDB#1`), `server` = `link`, C→S = towards the listener. Fields come from the server-internal annotations
  (`load_docs()["link_ann"]`: every annotation whose `dir` is not client-facing, the first per opcode wins), then
  the PDB layouts (which lack the 6-byte `ref` prefix, so a size issue there is expected); no `layouts.json`.
- The password of `0x0C5A` (payload bytes 260–295) is replaced by `*` in all three outputs unless `--show-secrets`.
  Nothing else is masked: the user name, the `0x0C0C`/`0x0C0F` validate key and the `0x0C37` token appear in clear.
- `--transcript DIR` writes only `<name>.txt` (format: `server/docs/technical/testing.md`), client-facing streams only,
  password not masked, refused when a client-facing stream has a gap, an unseeded (brute-forced) decrypt or a framing problem.
  Captures must use test accounts only.

## Outputs

| File | Content |
|---|---|
| `<capture>.decoded.txt` | One block per packet: index, frame number, time since the first frame, direction, stream (`login#1`, `wm#1`, `zone#2`…), opcode, name, payload size, then the decoded fields. Fields from generated layouts are tagged `(gen)`. Bytes no documented field covers are printed as `undocumented +N..: hex`. Problems are printed as `!! …`. pcapng packet comments appear as `===== frame N +t COMMENT: text` lines before the first packet of that frame or a later frame |
| `<capture>.report.md` | Streams (endpoints, seeds, gaps, decrypt decisions, reassembly problems), one row per (server, direction, opcode) with count, sizes seen, documented size, layout source, nonzero undocumented offsets and issues, the list of undocumented opcodes, and the value checks the C→S handlers make (for manual comparison) |
| `<capture>.json` | For P02. `comments[] {frame, time, text}`, `streams[]`, `packets[] {i, frame, time, abs_time, stream, server, dir, op, name, size, payload (hex), source, fields [[name, value]], issues[]}`, `report[]` (the table rows). Byte values are hex strings. Struct arrays are lists of objects |

`time` is seconds since the first frame of the file. `frame` is the 0-based frame index in the file
(Wireshark's frame number minus 1). A packet's frame is the last frame that delivered any of its bytes.

## How it decodes

1. **Capture formats.** pcap (µs and ns, both byte orders) and pcapng (SHB/IDB/EPB/SPB, `if_tsresol`, EPB
   `opt_comment`). Link types: Ethernet (with 802.1Q), DLT_NULL / DLT_LOOP (Npcap loopback), raw IPv4
   (101/228/12/14), Linux cooked (113). IPv4 TCP only.
2. **Streams.** A TCP connection whose one port is in the port map. The side with the mapped port is the server.
   Each direction is reassembled by relative sequence number (ISN from the SYN, else the lowest sequence
   seen): retransmitted and duplicate segments are dropped, out-of-order segments are sorted, holes are
   reported as gaps (`offset`, `missing bytes`).
3. **Framing.** README §1.1 (`len:u8`, or `0x00 len:u16` when the body is ≥ 256 bytes). At the start of a stream
   whose SYN was not captured, and after every gap, the decoder searches the next 4096 bytes for an offset where
   a chain of up to 4 frames parses and has known opcodes (at most one unknown in a chain of 3 or more).
   Skipped bytes are reported.
4. **Decryption (C→S only).** The index starts at `seed % 499` from the latest S→C `0x0807` whose frame is not later than the
   client packet, and runs across packets. Client packets with no seed before them (zone `0x0806`, a capture
   started mid-session, the first packet after a gap) are decrypted with a brute-forced start index: the one
   of 499 under which most of those packets have opcodes the server's client parser registers. Ties are broken
   by: the first packet of the stream decodes to the expected first opcode (`0x0C65` login, `0x0C0F` WM,
   `0x0806` zone), then index 0, then the lowest index. The chosen index, its score and the number of tied
   candidates are in the report.
5. **Field decode**, in order of preference:
   - `annotations.json` merged with `annotations/*.json` (same server, opcode and `dir`). Types: `u8/i8/u16/i16/u32/i32/u64/i64/f32`,
     `char[N]` (NUL-terminated, cp1252), `u8[N]` (hex), arrays `T[N]`, `T[N][M]`, counts that name an earlier field
     (`WORLD[count]`, `char[n]`), and structs from `structs`. Fields named `error`/`reason` are resolved with
     `client-error-codes.json`.
   - `re-data/exports/<bin>/layouts.json`: for C→S the entry of the client parser class (`CParserClient` for
     login/WM, `ShineObjectClass::ShinePlayer` for zone). For S→C the send sites whose fixed size equals the
     payload size (else the variable-size sites, else all sites with a size-mismatch issue). The first site's fields are decoded.
   - otherwise the payload is shown as hex.

## Validation checks (report)

| Check | Source | When it fires |
|---|---|---|
| Size | annotation | decoded end ≠ payload length, or a field needs more bytes than the payload has |
| Size | generated S→C | no send site has the observed size |
| Length check | `layouts.json` C→S `len_checks` (`== N` / `!= N`) | body length (opcode + payload) ≠ N. Applied even when an annotation exists |
| Constant | generated S→C | a field that every matching send site writes only as constants has another value |
| Undocumented nonzero | coverage of the decoded fields | payload offsets no field covers that are nonzero in any packet of that type |
| Undocumented opcode | `opcodes.json` + client parser registrations + layouts + annotations | opcode unknown in all of them |
| Handler checks (info) | `layouts.json` C→S field `checks` | listed only; the polarity of the comparison is unknown, so they are not judged |

## Limits

- IPv4 only; IP fragments are dropped; no IPv6.
- One TCP connection per 4-tuple: a reused client port in the same capture merges two connections (rare on Windows).
- The client→server cipher index after a gap is brute-forced, not computed (the number of length-prefix bytes lost in the gap is unknown).
- A single pre-seed packet (zone `0x0806`, 2 bytes) gives a weak brute force (typically 2–5 tied candidates); the result relies on the tie-break. *(inferred)* The zone's starting index before the seed is unknown; it only matters for that one packet.
- The resync search accepts a chain with one unknown opcode; on traffic dense with undocumented opcodes it can fail (reported as "could not find a frame boundary") or, rarely, sync to a wrong offset.
- The S→C "known" set includes server-to-server opcodes from `layouts.json`, so an internal opcode on a client port is not flagged as undocumented.
- `layouts.json` C→S `len_checks` and field `checks` are regex output: a length check from another code path of the handler can produce a false violation. Check the handler before reporting a contradiction.
- Generated layouts can contain fields beyond the send size, or overlapping writes. The decoder keeps the first non-overlapping field per offset.

## Tested

`--selftest` builds the same traffic as pcapng (Ethernet, with packet comments) and as pcap (DLT_NULL):
login with seed, encrypted `0x0C65` and `0x0C5A` (long form, split over two frames, out of order, with a
retransmit), `0x0C37` with a wrong length, `0x0C67`, a 291-byte `0x0C0A` split across frames, `0x0C09`,
an oversized `0x0C05`, an unknown opcode; a WM stream captured mid-session without seed (sync + brute force);
a zone stream with a pre-seed `0x0806`. It asserts opcodes, decrypted payloads, password masking, comments,
every report check, and resync after a dropped segment. No real capture existed when this was written.
